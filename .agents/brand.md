# vibelive brand

## Identity

vibelive is multiplayer for agentic coding terminals.
It ships as a CLI, npm library, and MCP server.
It belongs to the Vibe Suite of agentic CLI tools.

The product name is always `vibelive` in lowercase.

## Audience

The primary audience is developers who work with agentic coding CLIs.
They need to share a live session without corrupting the agent's input.

Teams, mentors, and observers are secondary audiences.
They need clear presence, chat, and control state.

## Promise

The shipped v0 provides host-authoritative collaboration over local WebSockets.
One driver controls the wrapped process at a time.
Other participants can read output, chat, and request control.

Describe relay fan-out, end-to-end encryption, and richer cursors as roadmap work.
Do not present those capabilities as shipped.

## Voice

- Be direct, calm, and technically precise.
- Lead with the collaboration outcome.
- Explain control with the word `driver`.
- State transport and security limits next to related claims.
- Use examples from Claude Code, Codex, Gemini, Grok/pi, and Kimi.
- Avoid hype, emojis, and vague scale claims.

## Names and claims

- Write `vibelive` in lowercase.
- Write `Vibe Suite` as two capitalized words.
- Write `@pooriaarab/vibe-core` for the installed package.
- Write `WriteArbiter` only when referring to the source class.
- Use `local/LAN` for the current transport boundary.
- Use `roadmap` for planned encrypted relay features.

Base shipped claims on `README.md`, `src/`, and current tests.
Use `docs/tech-spec.md` only for plans and technical targets.
Do not call a target, prototype, or launch scene a current capability.

## Assets

`branding/logo.png` is the owned icon.
It shows two white pointers over a blue rounded-square field.
Keep its black outlines and white pointer fills intact.

Launch media uses a text wordmark with amber emphasis on `live`.
That treatment belongs to the media templates, not the CLI.
